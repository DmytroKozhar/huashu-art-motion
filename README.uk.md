## Як це виглядає

<img src="assets/全风格总览.jpg" alt="Огляд кадрів із 35 художніх стилів" width="100%" />

По одному кадру з 35 прикладів: та сама дівчина, рудо-білий кіт і стіл проходять шлях від печери 40 000 року до н. е. до 2026 року. У кожній сцені щось рухається: зоряне небо Ван Гога обертається, колір перетікає між камінцями мозаїки, а розтікання туші переносить зображення в наступну епоху.

У цих 35 кадрах однакова композиція, бо це механіка швидкої подорожі історією мистецтва: стиль змінюється, сцена залишається. Це не універсальна композиція для відповідних стилів. Для нової теми потрібно спроєктувати власну сцену.

[Завантажити відео всіх стилів (MP4)](https://github.com/alchaincyf/huashu-art-motion/releases/latest).

У довгій панорамі персонаж іде зліва направо; на межі світів одночасно змінюється стиль середовища й самого героя. Репозиторій містить каркас та три приклади: єгипетський розпис → «Японський міст» Моне → 8-bit.

Перед передачею результату `qa.py` вимірює стабільність, швидкість рендеру, рух, плавність і можливі проблеми з розташуванням тексту. За робочим процесом оригіналу незалежний агент переглядає готове відео. Далі `deliver.py` запускає перевірку `film_gate.py`: за червоного статусу не копіює відео; за зеленого чи жовтого копіює його та створює опис передачі з фактами, записаними самим скриптом.

Оригінальний README наводить 17 бібліотек; у зафіксованому дереві вже 20 файлів `lib/*.js`. Це пояснює різницю між рекламним підрахунком і поточним складом файлів.

Є два головні маршрути рендеру. У режимі сцени рушій читає таблицю `eras.js` (або `eras_<назва>.js` через `--film`), завантажує сцени й переходи та надає `window.renderFrame(t)`. У режимі `--spec` Python передає JSON сторінці `clip.html`, а граматика будує фрагмент. В обох випадках Chromium обчислює кадри Canvas, Python передає PNG через канал у ffmpeg, який кодує відео. Локальні зображення у spec визначаються відносно самого JSON-файлу; `spec_assets.py` дозволяє серверу віддавати лише перелічені в ньому зовнішні файли.

## Передумови та перший рендер

Потрібні [uv](https://docs.astral.sh/uv/), Python відповідної версії (службові скрипти з метаданими часто вимагають 3.10+), `ffmpeg` і `ffprobe` у `PATH`, Playwright та його Chromium. Для команди встановлення навички через `npx` також потрібні Node.js/npm. Навичка — набір інструкцій і коду для агента, а не готовий графічний відеоредактор.

Наведена вище команда `npx` встановлює оригінальну upstream-навичку. Українські файли цієї гілки читайте безпосередньо у форку. Команди нижче — інструкції для майбутнього запуску після перевірки коду; під час перекладу залежності не встановлювалися й рендер не виконувався.

У повній копії репозиторію, включно з медіафайлами та шрифтами:

```sh
cd huashu-art-motion
# Одноразово завантажити браузер для Playwright.
uv run --with playwright playwright install chromium

# Один кадр постімпресіоністичної сцени на позначці 0,3 секунди.
uv run --with playwright python scripts/engine/render.py \
  --solo 09_postimp --stills 0.3 --out preview

# Параметризований фінансовий графік із готового прикладу JSON.
uv run --with playwright python scripts/engine/render.py \
  --spec scripts/engine/examples/t3_finance_chart.json --out finance-chart.mp4
```

`--stills` трактує `--out` як каталог для PNG, а звичайний рендер — як шлях до відеофайлу. Приклади навмисно зберігають оригінальні ідентифікатори.

## Робочий процес рендеру

1. Прочитайте [SKILL.uk.md](SKILL.uk.md), оберіть маршрут і складіть план кадрів. Структуру прикладів можна використати, але зміст, композицію та персонажів потрібно створити для власної теми.
2. Для власного фільму скопіюйте `scripts/engine/` у каталог проєкту. У режимі сцен змініть `eras.js`, додайте `scenes/<id>.js` і потрібну реєстрацію. Для фрагмента створіть JSON за прикладом відповідної граматики.
3. Перевірте окремі кадри через `--stills`, потім відрендерте рух. Для сцен частота за замовчуванням — 60 fps; для spec вона береться з JSON, а за відсутності поля — 30 fps. Узгодьте розміри та fps перед монтажем.
4. Запустіть QA для фрагмента або проєкту, перегляньте кадри з попередженнями й усе відео зі звичайною швидкістю.
5. Після незалежного перегляду застосуйте `deliver.py`; виправте причини червоного статусу та повторіть рендер і перевірки.

```sh
# Сцена: 3 секунди, 30 кадрів/с, без лічильника.
uv run --with playwright python scripts/engine/render.py \
  --solo 09_postimp --from 0 --to 3 --fps 30 --no-counter --out scene.mp4

# Прозорий параметризований фрагмент: ProRes 4444 у контейнері MOV.
uv run --with playwright python scripts/engine/render.py \
  --spec scripts/engine/examples/t3_finance_chart.json --alpha --out chart.mov

# QA конкретного прикладу.
uv run scripts/qa.py --spec scripts/engine/examples/t3_finance_chart.json --out qa/finance

# Передача вже перевіреного відео; --qa вказує на каталог qa.json.
uv run scripts/deliver.py finance-chart.mp4 --root . --qa qa/finance --out output/
```

Для spec тривалість перетворюється на `round(duration × fps)` кадрів. Звичайний вихід — H.264 `yuv420p`, для фрагментів із ключовим кадром щосекунди. `--alpha` у режимі spec дає ProRes 4444 з альфа-каналом. Звук додається окремо через `--audio`; без нього результат німий. Помилки `pageerror` або `console.error` призводять до ненульового завершення після рендеру.

Опис передачі має початкову назву `output/交付说明.md`. Скрипт шукає незалежні рецензії у `<проєкт>/审片/*.md`; ці назви не перекладаються, бо вони є частиною програмного контракту. Перевірка наявності рецензії не означає перевірки її змісту.

## Обмеження та стан перевірки

- Це переклад документації й коментарів, а не підтвердження працездатності у вашому середовищі. Перевірки цієї роботи статичні; сторонній код не запускався.
- Вісім граматик мають параметризовані приклади. Дев'ята, з ведучим, потребує власних зображень персонажа. Приклади повних відео — знімки коду, а не повністю укомплектовані проєкти для негайного рендеру.
- Демонстраційні композиції не замінюють дизайн нового відео. Один параметризований фрагмент довший за 8 секунд викликає попередження, але рендерер технічно не забороняє його.
- QA та `film_gate.py` використовують евристики. Вони не гарантують художньої якості, правильності тексту чи узгодженого стилю. Низька частка швидкого руху може блокувати навмисно спокійне відео.
- Оригінальний посібник описує червоний статус за частки швидкого руху `< 0.035`, жовтий за `< 0.06`, перевірку порожніх ділянок у середині відео від 0,3 с і синьо-фіолетового фону понад 30%. Точну поведінку визначають поточний код, параметри й контекст. `--allow-blue-purple "причина"` — явний виняток для відповідної теми.

## Історія проєкту

На початку жовтня 2026 року автор побачив у X 15-секундну анімацію Tak ([@cherry_mx_reds](https://x.com/cherry_mx_reds/status/2106095190285144331)): дівчина й кіт проходять 40 000 років історії мистецтва, кожна епоха триває близько секунди, а предмети всередині картин рухаються.

Він попросив Claude відтворити її. Перша версія лише переходила між нерухомими картинами; автор її відхилив. Замість цього процес почали з розбору переходів, ритму та ділянок руху, після чого зображення малювали й оживляли пошарово кодом.

Завданням було також накопичувати досвід. Тому навичка містить не лише код, а й дієві прийоми в `references/07-正面经验.md`, відомі проблеми та обмеження стилів. Потім чотири групи агентів, які читали лише навичку, створили ще 20 незнайомих їй стилів; їхні інструменти об'єднали в бібліотеки. Додали вісім граматик пояснювальних відео для YouTube та інтегрували їх у власний процес озвучених відео. Також створили «Huashu подорожує відомими картинами»: 23 стилі, 2 хвилини 8 секунд, від печер до 2026 року. Каркас і три сцени включено до репозиторію.

## Необов'язкові медіаможливості

Для базової анімації кодом не потрібні облікові записи сервісів голосу чи зображень. Наявні матеріали використовуються першими; нові генеруються лише відповідно до вибору користувача й доступного середовища. Підтримуються системні голоси macOS і власний клонований голос у Volcengine, а для зображень — імпорт файлів та підключення поточних інструментів агента/MCP.

- [Голос і приватна конфігурація](references/capabilities.md): налаштування за потреби, можливість пропустити, сумісність зі старим `koubo`.
- [Інструменти зображень](references/images.md): план → виклик інструмента агентом → перевірка й збереження матеріалів.
- [Сумісність та межі перевірки](references/compatibility.md): upstream повідомляє про успішне встановлення й повторне встановлення у трьох агентів та онлайн-регресію Codex; онлайн-перевірки Claude Code/Kimi були заблоковані умовами тестових облікових записів і залишалися непідтвердженими.
- [Супровід, розширення й випуски](CONTRIBUTING.md): розділення публічних значень і приватних налаштувань, збереження особистого вибору при оновленні, перевірка фактичних Git-об'єктів випуску.

Оригінал пропонує почати з `python scripts/capabilities.py status --explain`. Нові можливості спочатку не обрані й не авторизовані: наявність ключа чи інструмента не означає дозволу витрачати кошти. Окремий виконавець API зображень передбачений як майбутнє необов'язкове розширення; автоматичного перемикання постачальника немає.
