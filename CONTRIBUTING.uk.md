# Супровід і розширення

Український переклад [оригіналу](CONTRIBUTING.md) зі знімка `64cb27271ee0ad3375298e2890b33cbec36d4051`. Приклади команд збережено; це документація, а не повідомлення про виконання цих команд.

Спільний код і загальні рекомендації зберігайте в пакеті; особисті платформи, голоси та посилання на облікові дані — поза каталогом встановлення. Не перетворюйте особистий досвід на дозвіл за замовчуванням для всіх.

## Локальні перевірки

```sh
python -m pip install requests Pillow
# 另需系统安装ffmpeg/ffprobe；不会在正常Skill激活时自动安装
python -m unittest discover -s tests -v
```

Додатково в системі мають бути встановлені ffmpeg/ffprobe; звичайна активація Skill не встановлює їх автоматично.

Модульні тести не викликають справжні сервіси синтезу мовлення чи генерації зображень. Перевірки на реальних хостах описано в [записі про сумісність](references/compatibility.uk.md). Для нового адаптера потрібно чітко визначити конфігурацію, виявлення можливостей, контракти запитів і вихідних даних та поведінку в разі помилок. Не можна оголошувати сумісність з іншою платформою лише після заміни base_url.

## Міст до інструментів зображень

Прочитайте [настанови щодо зображень](references/images.uk.md). Хост надає фактичні описи інструментів, агент виконує виклики, а CLI формує план і перевіряє результати. Квитанція не є підписаним платформою підтвердженням походження. Потрібно охопити випадки наявних зображень, забороненої генерації, відсутніх інструментів, невідомої оплати, дозволів на референсні зображення та невдалої генерації.

Окремий виконавець API зображень залишається необов’язковим розширенням. Ця версія не встановлює його автоматично, не реєструє облікові записи й не використовує стан входу інших агентів.

## Збереження налаштувань користувача під час оновлення

Каталог встановлення можна замінювати; користувацький media.json не можна записувати в нього. Старі конфігурації отримують нові поля через об’єднання зі значеннями за замовчуванням. Нові можливості за замовчуванням залишаються невибраними й недозволеними; наявні голоси не перенавчаються й не скидаються автоматично. Якщо змінюється значення полів, надайте явні способи міграції та відкату.

## Перевірки перед випуском

Після перегляду змін додайте до індексу спільні файли цього випуску, а потім створіть перелік файлів:

```sh
python scripts/check_release.py manifest --repo .
git add release-manifest.json
python scripts/check_release.py check --repo . --ref INDEX
# 提交后核对全部待发提交，base替换为实际远端基线
python scripts/check_release.py check --repo . --ref HEAD --base origin/main
```

Після коміту перевірте всі коміти, призначені до випуску; замініть base на фактичну віддалену базову ревізію.

Перевіряйте об’єкти Git, а не лише файли на диску; перевірка також виявляє облікові дані, записані в проміжному коміті й згодом видалені. Перелік засвідчує лише відповідність набору перевірених файлів і не замінює перегляду коду, приймання реальних медіарезультатів та перевірки ліцензій. Заборонено обходити перевірки або переписувати історію, щоб удавати перший випуск.

Повторно використовуючи код, дотримуйтеся ліцензійних меж оригінальних шрифтів, даних про порядок написання штрихів і демонстрацій персонажів. Особисті відгуки залишайте в особистих налаштуваннях; до спільної документації додавайте лише методи й досвід роботи з інтерфейсами, підкріплені відтворюваними доказами, із зазначенням дати, сфери застосування та стану перевірки.
