# Необов’язкові зображення: наявні матеріали й генерація поточним агентом

Український переклад [оригіналу](images.md) зі знімка `64cb27271ee0ad3375298e2890b33cbec36d4051`. Приклади команд збережено; це документація, а не повідомлення про виконання цих команд.

Інтеграція зображень має дві частини: агент перевіряє поточні інструменти й викликає їх за дозволом користувача; скрипт розбирає вибір, перевіряє результати та зберігає їх у проєкті. Скрипт не імітує інструменти хоста, не використовує стан входу інших агентів і не перемикає API зображень автоматично.

## Спочатку завдання, потім конфігурація

Наявні зображення імпортуйте безпосередньо через `use-image`. Для програмної анімації, яка не потребує зображень, пропустіть цю сторінку. Перед новою генерацією прочитайте явні вподобання в правилах, завантажених для поточного завдання, а потім конфігурацію цього інструмента. Якщо користувач уже попросив згенерувати зображення, дійте відповідно до фактичних інструментів і наданих дозволів; не змушуйте його повторно відповідати лише заради заповнення конфігурації.

```sh
# S为本次实际加载的skill目录
python "$S/scripts/capabilities.py" image-status
python "$S/scripts/capabilities.py" use-image --file 原图.png --out <项目>/配图/素材.png
```

S — каталог skill, фактично завантажений для поточного завдання.

`preferences.image.mode` підтримує `unconfigured/off/existing/generate`; provider — точний ID поточного інструмента або auto. `off` означає вподобання не генерувати за замовчуванням, яке можна перекрити явним запитом на генерацію цього разу. `policy.image_generation=deny` — заборона, яку тимчасові прапорці дозволу не перекривають. Явну користувацьку «заборону» зберігайте в policy, а не лише в mode.

Коли конфігурації бракує вперше, запитайте лише про вибір: наявні матеріали, дозвіл на генерацію поточним інструментом або пропуск. `skip --capability image --scope task` не записується на диск; `--scope user` означає подальше ручне ввімкнення. Вибір лише для поточного завдання не зберігайте як довгострокове типове налаштування. Наявна конфігурація голосу залишається чинною після оновлення, а нова можливість зображень залишається невибраною й не отримує дозволу автоматично.

## Знімок поточних інструментів

Агент читає назви й схеми інструментів зі списку, фактично доступного в поточному сеансі, або через офіційний пошук інструментів хоста, перевіряє підтримувані операції й записує знімок у межах завдання. Не можна робити висновки через пошук Key, за встановленими skill або назвою агента. Якщо інструментів немає, запишіть `tools: []`.

```json
{
  "host": "codex",
  "session_id": "本次任务唯一标识",
  "observed_at": 0,
  "tools": [{
    "id": "当前实际工具ID",
    "kind": "host",
    "operations": ["generate", "edit"],
    "reference_images": true,
    "transparent_background": true,
    "cost": "subscription",
    "network": "cloud"
  }]
}
```

Цей приклад не є заявою про наявні можливості: у `observed_at` потрібно вказати поточний Unix-час, а властивості й ID інструмента мають походити з його фактичної поточної схеми. Знімок чинний 15 хвилин. host може бути codex, claude-code, kimi або other; kind — host чи mcp. Тип оплати: subscription/paid_api/unknown/none; мережа: cloud/local. Підписка не означає відсутності лімітів; якщо оплата невідома, використовуйте unknown, а не none.

Усі три хости використовують цей спільний контракт. Наявність image_gen в одному сеансі Codex не означає, що він доступний у кожному інтерфейсі продуктів Codex. Claude Code/Kimi також можуть використовувати відповідний MCP-інструмент зображень, якщо він доступний; інакше імпортуйте наявні зображення або опишіть матеріали, які ще потрібно створити. Не вигадуйте для цих двох хостів вбудованих інструментів з однаковою назвою.

## План → виконання хостом → приймання

JSON вимог:

```json
{
  "prompt": "用户确认的图片描述",
  "operation": "generate",
  "references": [],
  "transparent_background": true,
  "min_width": 512,
  "min_height": 512
}
```

Для редагування використовуйте edit і надайте референсні файли; відносні шляхи відлічуються від JSON вимог. Скрипт перевіряє можливість декодувати референсні зображення й зберігає їхні хеші; подальша зміна файлів робить старий план недійсним.

```sh
python "$S/scripts/capabilities.py" image-plan --request 需求.json \
  --host-tools 当前工具.json --session 本次标识 --mode generate \
  --allow-image-generation --allow-cloud --out 执行计划.json
```

Прапорці дозволу лише виражають уже наданий користувачем дозвіл для цього завдання. Завантаження референсних зображень у хмару додатково потребує `--allow-reference-upload`; явно платний API — `--allow-paid-api`; невідома оплата — `--allow-unknown-image-cost`. Постійний дозвіл можна зберегти у відповідних полях policy. Проєкт може встановлювати лише deny, але не надавати ці права. Спочатку враховуйте заборони; якщо серед кількох дозволених інструментів неможливо однозначно вибрати, поверніть needs_selection, не вгадуйте платформу самовільно.

Після отримання `host_action_required` агент викликає інструмент відповідно до його справжньої схеми. План задає змістовні вимоги, а не універсальне міжплатформне тіло параметрів. Записуйте квитанцію лише після успішної генерації:

```json
{
  "status": "success",
  "plan_id": "执行计划中的ID",
  "session_id": "本次标识",
  "tool_id": "实际调用工具ID",
  "output_sha256": "实际输出文件SHA256"
}
```

Зберігайте фактичний запис виклику інструмента як підтвердження. Квитанція — це наданий агентом запис виклику, а не підписане платформою засвідчення; лише читання метаданих PNG не доводить, якою моделлю його створено.

```sh
python "$S/scripts/capabilities.py" accept-image --plan 执行计划.json --receipt 回执.json \
  --host-tools 当前工具.json --session 本次标识 --file 宿主输出.png \
  --out <项目>/配图/正式素材.png --allow-image-generation --allow-cloud
```

Приймання повторно перевіряє поточні дозволи, пов’язані із зображеннями налаштування, інструмент, сеанс, референсні зображення, хеш файлу, фактичні розміри й прозорі пікселі. План чинний 1 годину. Якщо знімок можливостей прострочено, спочатку оновіть його; не змінюйте старий план, удаючи, що він досі чинний. Якщо вже існує файл зображення або супровідний файл, перезапис не виконується. Підтримуються статичні PNG/JPEG/WebP; потрібен Pillow, який інструмент не встановлює автоматично. Зміст зображення й відповідність ідентичності в референсі все одно потрібно перевіряти візуально: хеш і розміри не замінюють перегляду.

Після успішної перевірки файл копіюється до проєкту, а поруч записується JSON із розмірами, прозорістю, SHA, ID інструмента, зв’язком із планом і `provenance: agent_reported_tool_call`. Не використовуйте кеш агента як остаточне джерело матеріалів проєкту й не стверджуйте, що назву моделі перевірено, якщо сервер її не повернув.

## Розширення й повернення досвіду

Додаючи адаптер API зображень, спочатку виберіть реального постачальника, а потім реалізуйте його протоколи автентифікації, запитів, вихідних даних і помилок та напишіть контрактні тести успіху й відмови. URL, що називає себе OpenAI-compatible, не стає автоматично придатним бекендом; ця версія не містить універсального виконавця API чи автоінсталятора. Наявні MCP-інструменти належать до каналу інструментів поточного агента; виконуйте їх за їхньою схемою.

2026-10-08: P2 запровадив інтерфейс «вибір → дія хоста → приймання матеріалу». Перед повторним використанням прочитайте цю сторінку й актуальні інструкції постачальника інструмента. Для відтворюваних помилок додавайте тести й виправляйте вихідну логіку; особисті вподобання записуйте лише до приватної конфігурації. Голос і зображення вмикаються окремо; оновлення не розширює наявні дозволи. Результати детермінованого приймання й висновки про візуальну якість фіксуйте окремо.
