# Необов’язкове озвучення: налаштування, пропуск і наявні матеріали

Український переклад [оригіналу](capabilities.md) зі знімка `64cb27271ee0ad3375298e2890b33cbec36d4051`. Приклади команд збережено; це документація, а не повідомлення про виконання цих команд.

На цій сторінці описано необов’язкове озвучення: наявні аудіозаписи, системний голос macOS і клонування голосу Volcengine (火山). Роботу із зображеннями описано в [настановах щодо зображень](images.uk.md). Конфігурація використовує один спільний зовнішній файл; жодних сервісів чи плагінів не встановлюється.

## Перед використанням

Перевіряйте можливості лише тоді, коли завдання потребує голосу; для німої анімації відразу переходьте до візуального процесу. Якщо користувач уже надав придатну звукову доріжку, використовуйте її, якщо він явно не просить переозвучити. Для суто аудіозавдань не запускайте проєктування анімації чи перегляд відео.

`S` означає фактично прочитаний у цьому завданні каталог skill, а не фіксований каталог на комп’ютері автора чи каталог певного агента. Claude Code, Codex і Kimi використовують однакові виклики CLI без спеціальних хуків хоста.

```sh
python "$S/scripts/capabilities.py" status --explain
# 需要读取已信任项目的偏好时才加--project
python "$S/scripts/capabilities.py" status --project <项目> --explain
```

Додавайте --project лише коли потрібно прочитати вподобання вже довіреного проєкту.

Перевірка читає лише конфігурацію цього інструмента, визначені джерела облікових даних вибраного адаптера та необхідні локальні залежності; мережевої перевірки немає. `configured_unverified` означає, що умови для виклику виконано, а не що обліковий запис чи якість голосу перевірено. Лише `needs_configuration` потребує вибору способу озвучення; `prompt:false` означає, що користувач раніше вибрав ручне налаштування, тому не слід знову запитувати з власної ініціативи. Успіх фактичного запиту визначають результат і квитанція.

Коли конфігурації бракує вперше, запитайте лише про потрібний зараз вибір: використати запис, системний голос, власний клонований голос або пропустити. Якщо користувач уже визначив вибір, виконуйте його. Для нових хмарних викликів, оплати чи навчання використовуйте наявний дозвіл для поточного завдання; якщо дозволу немає, поясніть, чого бракує. Не просіть користувача вставляти Key у чат.

## Область збереження й пропуск

Звичайний вибір діє лише цього разу. Зберігайте його як користувацьке значення за замовчуванням лише після слів «надалі», «за замовчуванням» або «запам’ятай». Звичайна конфігурація розміщується поза каталогом встановлення: на macOS/Linux — `$XDG_CONFIG_HOME/huashu/media.json` (якщо змінну не задано — `~/.config/huashu/media.json`), на Windows — `%APPDATA%/huashu/media.json`. `HUASHU_CONFIG_HOME` перевизначає каталог, а `--config` замінює стандартний користувацький файл.

Зібравши вибір користувача, агент формує JSON без чутливих даних і передає його скрипту для запису. Скрипт не блокується в очікуванні інтерактивного введення зі stdin.

```sh
# 示例JSON：{"preferences":{"voice":{"mode":"system"}}}
python "$S/scripts/capabilities.py" configure --scope user --input <选择.json>
python "$S/scripts/capabilities.py" skip --scope task  # 不落盘，本次跳过
python "$S/scripts/capabilities.py" skip --scope user  # 以后手动启用，不反复问
python "$S/scripts/capabilities.py" reset --field preferences.voice
python "$S/scripts/capabilities.py" reset --field onboarding.voice
```

У прикладі JSON вибрано системний голос. Пропуск у межах task не записується на диск і діє цього разу; пропуск у межах user означає подальше ручне ввімкнення без повторних запитань.

«Пропустити цього разу» фіксується у стані поточного завдання; наступна дія не повинна знову відкривати анкету. Відсутність відповіді не є згодою й не дозволяє виконати configure. Якщо пакетному виконанню бракує обов’язкової конфігурації, воно повертає причину й ненульовий код завершення. Німий попередній перегляд можна надати лише якщо користувач погодився на базовий перегляд; його не можна називати завершеним роликом з озвученням.

Пріоритет уподобань: параметри поточного виклику → уподобання проєкту → уподобання користувача → спільні типові значення. Проєктний `<项目>/.huashu/media.json` приймає лише обмежений набір уподобань і політики `deny`; у ньому не можна зберігати облікові дані, особисті прив’язки голосів або надавати дозволи. `status --explain` указує джерело кожного поля. Запис захищено міжпроцесним блокуванням; `--expected-revision` запобігає перезапису нової конфігурації повним набором змін, підготовлених на основі старої.

## Три способи роботи зі звуком

```sh
# 1. 复用已有音频，逐字节保留并生成元数据；若不需要复制，可直接引用原轨
python "$S/scripts/capabilities.py" use-audio --audio 原录音.wav --out <项目>/音频/口播.wav
# 2. 系统声音：仅macOS，固定48kHz WAV；中文默认从已安装普通话音色中选
python "$S/scripts/capabilities.py" say "要念的原文" --mode system --out <项目>/音频/口播.wav
# 3. 已配置并已授权的火山复刻
python "$S/scripts/capabilities.py" say "要念的原文" --mode clone --out <项目>/音频/口播.wav
# 旧调用保持兼容，共用同一套配置
python "$S/scripts/koubo.py" say "确认的补配台词" --out <项目>/音频/补配.wav \
  --fit 3.5 --match 原音轨.wav --match-ss 10 --match-t 3.5
```

1. Повторне використання наявного аудіо зберігає його побайтово й створює метадані; якщо копія не потрібна, можна посилатися безпосередньо на початкову доріжку.
2. Системний голос доступний лише на macOS і створює WAV із фіксованою частотою 48 кГц; для китайської за замовчуванням вибирається встановлений голос путунхуа.
3. Клонування Volcengine має бути налаштоване й дозволене. Старий виклик koubo.py залишається сумісним і використовує ту саму конфігурацію.

Наявні вихідні файли не перезаписуються. Після успіху поруч записується `音频文件.json` із тривалістю, частотою дискретизації, SHA та джерелом. Для клонування фіксується запитана модель, без твердження, що сервер підтвердив фактично використану модель. Сирий PCM спочатку перевіряється як аудіо в контейнері, а потім експортується в s16le; частота дискретизації й моноформат записуються в супровідний файл. До системних голосів не можна застосовувати параметри моделі й темпу Volcengine.

Спільне значення за замовчуванням — «спосіб озвучення не вибрано», а не голос автора. Рекомендовані типові параметри Volcengine: expressive, режим відтворення оригінального голосу, темп 0; користувач може змінити їх у `provider_options.volcengine`. Особисті налаштування можуть зберігати інший темп і голос. Повний набір полів наведено в `schemas/media.schema.json`; не вгадуйте їх.

Наявний на платформі голос не потрібно навчати повторно:

```sh
python "$S/scripts/capabilities.py" bind --name narrator --speaker-id S_xxx --default
```

bind лише реєструє локальний псевдонім: не викликає платформу, не змінює попередній `~/.koubo/voices.json` і не вмикає хмарні виклики автоматично. `--default` змінює лише типове посилання; спосіб генерації все одно потрібно встановити на clone.

## Налаштування й дозволи Volcengine

Облікові дані читаються зі змінних середовища процесу. Також можна вказати наявний файл у приватному `bindings.volcengine.env_file` або тимчасово через `KOUBO_ENV`. Змінні середовища мають пріоритет. Автоматичного пошуку .env у поточному каталозі, домашньому каталозі чи робочій області автора немає. Конфігурація зберігає назви змінних і посилання на файли, а не значення Key.

Для ввімкнення хмарного клонування потрібні `preferences.voice.mode=clone`, голос, посилання на який можна розпізнати, і значення allow для `policy.cloud` та `policy.paid_api` або явний дозвіл користувача для цього завдання. `--allow-cloud` і `--allow-paid-api` лише виражають уже наданий дозвіл для поточного завдання; вони не є засобом обходу правил і не можуть перекрити deny. Якщо користувач змінює власну заборону, спершу явно змініть відповідну конфігурацію; обмеження хоста й організації залишаються чинними. Проєкт може лише посилювати обмеження, а не надавати дозволи.

Мережевий проксі контролюється особистим `bindings.volcengine.trust_env`; спільне типове значення враховує середовище. Не нав’язуйте всім користувачам висновки з несправності проксі на одному комп’ютері. Базове налаштування й наявне аудіо потребують лише стандартної бібліотеки Python. Для перевірки аудіо потрібен ffprobe, для системного голосу й підгонки — ffmpeg, а для Volcengine додатково requests. Якщо залежності відсутні, повідомте про це, не встановлюйте їх автоматично.

Навчання є окремою дією: потрібно явно визначити слот голосу та отримати дозвіл на це навчання. `--force` пропускає лише перевірку низького рівня сигналу, але не дозвіл. Лише передавання `--default` робить результат навчання типовим записом у реєстрі.

```sh
python "$S/scripts/koubo.py" train --audio 自己的录音.wav --speaker S_xxx --name 我的声音 \
  --allow-cloud --allow-paid-api --allow-voice-training
```

Навчання змінює віддалений голос. Прапорці дозволу з прикладу можна використовувати лише після фактичної згоди користувача; це не стандартний підготовчий крок перед синтезом.

## Приймання результатів і помилки

Підгонка зберігає попередній підхід «грубе коригування + atempo» і виконує щонайбільше 3 генерації; кожна може бути платною. Якщо остаточне відхилення перевищує ±0,05 секунди, повертається помилка й зберігається кандидат `.unfitted`; його тривалість не оголошується відповідною вимогам. Для синтезу обов’язково отримати від сервера повідомлення про успішне завершення. Майже порожні, беззвучні результати та відповіді з помилкою не зберігаються як остаточний продукт. Після мережевого тайм-ауту запит міг уже бути прийнятий; позначайте результат як невизначений і не повторюйте запит наосліп.

Для остаточного відео все одно потрібно дослівно перевірити текст і прослухати власні назви; CLI не виконує автоматично вибір із трьох аудіокандидатів або ASR. Для додаткового озвучення перевіряйте стики, субтитри й часову шкалу зображення. Якщо вже використовується video-pipeline, застосовуйте його процес повернення звуку в монтаж і роботи із субтитрами; незалежні користувачі можуть використовувати власний монтажний проєкт.

Для відтворюваних збоїв інтерфейсів спочатку додайте тести, а потім виправляйте код. Загальні закономірності параметрів записуйте тут або в `口播API.md`, зазначаючи дату й сферу застосування. Особистий вибір після прослуховування зберігайте у приватних налаштуваннях чи приватних відгуках, не перетворюючи його на обов’язкову вимогу для всіх. Виправляючи старі висновки, редагуйте оригінальний текст. Оновлення конфігурації не повинно очищати вподобання чи автоматично вмикати нові можливості.
